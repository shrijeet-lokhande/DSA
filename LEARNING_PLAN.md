# Learning milestones

Track your progress topic by topic. Try the exercises before looking up solutions; write down the invariant or reason each approach is correct.

## C++ and problem-solving foundations

- **01 Fundamentals:** types, `const`, input/output, conditionals, loops, functions, references, scope, and basic debugging. Practice arithmetic, digit processing, and simple simulation.
- **02 Strings and arrays:** `string`, arrays, `vector`, indexing, iteration, sorting, two pointers, and prefix sums. Practice reverse/palindrome checks, pair sum, and range sums.
- **03 STL:** iterators, algorithms, `pair`, `map`, `unordered_map`, `set`, `stack`, `queue`, `deque`, and `priority_queue`. Practice frequency counts, deduplication, and top-k.
- **04 Complexity:** Big O, worst-case analysis, amortized vector append, and memory tradeoffs. Estimate before coding, then compare approaches.

## Core data structures and algorithms

- **05 Recursion:** base case, progress toward the base case, call stack, memoization, and backtracking. Practice subsets, permutations, and combinations.
- **06 Search and sort:** binary search boundaries, `lower_bound`, custom comparators, merge sort ideas, and interval problems.
- **07 Linked lists:** node pointers, traversal, insertion/deletion, reversal, and cycle detection.
- **08 Stacks and queues:** monotonic stack, deque windows, and queue-based BFS patterns.
- **09 Trees:** tree traversals, BST invariants, recursion on trees, and heap operations.
- **10 Graphs:** adjacency lists, BFS/DFS, connected components, topological sort, shortest paths, and disjoint set union.
- **11 Greedy:** interval scheduling, sorting-based choices, and explaining why a choice can be made safely.
- **12 Dynamic programming:** state definition, transition, base cases, memoization, tabulation, and space optimization.
- **13 Bit manipulation:** binary representation, masks, shifts, XOR, and subset enumeration.

## For every problem

1. Restate the input, output, and constraints.
2. Work a small example by hand.
3. Start with a correct simple approach and estimate its complexity.
4. Improve it only when constraints require it.
5. Test normal, boundary, and larger inputs.
6. Explain the invariant and complexity in a short note beside your solution.
